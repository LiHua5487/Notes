
既然能对随机变量讨论 minimum description length (MDL) ，那确定性对象 $x$ （编码成 01 串，记为 $x\in \{0,1\}^*$ ）的 MDL 呢？可以使用一个程序 / 算法去描述，这个程序的输出对象就是 $x$ ，为了形式化的描述程序的计算过程，有了**通用图灵机**的概念

>普通图灵机只能干一件事（比如只能做加法），通用图灵机可以模拟其它任何普通图灵机，只需给它一个程序 $p$ （比如一个加法程序），它就能模拟这个程序的运行过程（输入 $a,b$ ，输出 $a+b$ ）

**K-Complexity**：关于一个通用计算机 $\mathcal{U}$ ，设程序 $p$ 对应的输出为 $\mathcal{U}(p)$ （没有任何输入直接运行），则二元串 $x$ 的 K-Complexity 就是能输出 $x$ 的程序的最小长度

$$
K_{\mathcal{U}}(x) = \min_{p:\mathcal{U}(p)=x} l(p)
$$

关于不同的图灵机，一个二元串的 K-Complexity 的差值是一个有限常数

$$
\sup \lvert K_{\mathcal{U}_1}(x) - K_{\mathcal{U}_2}(x) \rvert \leq \text{const}(\mathcal{U}_1, \mathcal{U}_2)
$$

>可以把 “选哪个 $\mathcal{U}$ ” 理解成 “选哪种编程语言”，比如 Cpp 与 Python ，而 $\mathcal{U}_1$ 与 $\mathcal{U}_2$ 之间的转换是固定的

---

那怎么得到最短代码？一个简单的想法是直接遍历所有程序看能不能输出 $x$ ，但是这个方法的问题是，一个程序不一定能在有限步执行完，即不可停机，那遍历就卡在这了，所以需要先判断一个程序能不能停机，但这是做不到的

**停机问题 Halting Problem** ：存不存在一个通用的算法，给定一个程序 $p$ 以及输入 $x$ ，判断能不能停机
- 假设存在一个判断器 $H(p,x)$ ，判断 $p(x)$ 是否停机
- 构造程序 $D(y)$ 
	- 如果 $H(y,y)=1$ （程序 $y$ 在输入自己时会停机），就让 $D(y)$ 死循环
	- 如果 $H(y,y)=0$ ，就让 $D(y)$ 可停机
- 考虑 $D(D)$ 能不能停机
	- 如果 $H(D,D)=1$ ，根据构造方式，$D(D)$ 会死循环，判断错误
	- 如果 $H(D,D)=0$ ，根据构造方式，$D(D)$ 会停机，判断错误
- 所以不存在一个通用的停机判断算法

那 $K_{\mathcal{U}}(x)$ 到底可不可计算
- 设存在程序 $p_0$ ，给定输入 $x$ ，得到输出 $p_0(x) = K_{\mathcal{U}}(x)$ 
- 可以找到一个二元串 $s$ ，满足 $p_0(s) >> l(p_0)$ ，比如 $p_0(s) > 10^{l(p_0)}$  
- 把找到这个二元串 $s$ 的过程写成一个程序 $p_1$ 
	1. 令 $i=1$ 
	2. 运行 $p_0$ 计算 $K_{\mathcal{U}}(x_i)$ （把所有二元串从短到长排成 $x_1,x_2,\cdots$）
	3. 如果 $K_{\mathcal{U}}(x_i) > 10^{l(p_0)}$ ，输出 $x_i$ 
	4. 否则 $i \leftarrow i + 1$ ，跳转到第 2 步
- 考虑 $p_1$ 的长度，其包含了 $p_0$ ，包含了其它一些代码（比如条件、赋值、跳转），还包含 $10^{l(p_0)}$ 这个数，则 $l(p_1) = l(p_0) + \text{const} + \log 10^{l(p_0)} < 10^{l(p_0)}$ 
- 根据 K-Complexity 的定义，$p_1$ 是可以输出 $s$ 的程序，则 $K_{\mathcal{U}}(x) \leq l(p_1)$ ，这与 $K_{\mathcal{U}}(s) = p_0(s) > 10^{l(p_0)} > l(p_1)$ 矛盾
- 所以不存在计算 $K_{\mathcal{U}}(x)$ 的通用算法
