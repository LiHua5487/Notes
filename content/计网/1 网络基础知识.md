
# 计算机网络的构成

## 从两台计算机到一个网络

先设想一个最简单的情况：你有两台电脑 A 和 B，A 上面有一张照片，你想把它发送给 B ，最直接的办法，是用一根线把两台电脑连接起来，这样两台计算机之间就有了可以传递信息的通道

我们把 A、B 这样的设备叫作**结点（Node）**，把连接它们的通信通道叫作**链路（Link）**，最基础的网络可以理解成：网络 = 结点 + 链路

现在还有个问题：照片怎么能通过一根线传过去？电脑中的文字、图片、视频，最终都可以表示为一个二进制的 0/1 数字串，每个数字是一位（bit），但 0 和 1 只是数字，不会自己从电脑 A 跑到电脑 B ，所以电脑还需要某种办法，把数字信息转换成能在外界传播的信号，比如
- 电线中，可以利用电信号
- 光纤中，可以利用光信号
- 无线通信中，可以利用无线电信号

负责让电脑连接网络、收发网络数据的硬件，叫**网卡（NIC，Network Interface Card）**，比如笔记本电脑通常内置无线网卡，可以收发 Wi-Fi 信号，而信号经过的东西，就叫**传输介质**

## 局域网与网络设备

两台电脑直接连接很简单，但假如有更多的设备，总不能每两台之间都单独拉一根线，更自然的办法，是让这些电脑连接到一台公共设备，再由它负责把数据送往合适的电脑，这种设备叫做**交换机（Switch）**

交换机的一项重要工作，就是让多台设备可以一个共同的网络进行小范围通信，这样的网络有一个名字：**局域网（LAN，Local Area Network）**，比如家庭、办公室、学校内部的网络都可以是局域网

>蓝牙耳机这种短程连接的网络，则称为个域网（PAN，Personal Area Network），大一些的还有城域网、广域网

那设备怎么接入这个局域网呢？有两种非常常见的方式
- **WiFi**：与附近的**无线接入点（AP，Access Point）** 通信，比如手机通过无线电信号接入局域网
- **以太网（Ethernet）**：一套局部网络通信技术，常见的形式是有线以太网，比如电脑通过网线接入局域网

但局域网只允许有限范围内的通信，还不能访问外面的互联网，这时就需要**路由器（Router）**，它负责连接不同的网络，并将数据从一个网络转送到另一个网络，家用路由器常常集成了AP、交换机、路由器的功能，被封装进一个盒子里

## 接入网与互联网

假设你家有一个局域网，朋友家也有一个局域网，学校和公司各有自己的网络，如果这些网络都不与外界连接，那么它们只能在自己的范围内通信，所以还需要有人把这些不同的网络连接起来，许许多多网络相互连接，就形成了我们所说的**互联网（Internet）**

那咋才能连到互联网呢？家庭办理的**宽带**，就是一种常见的互联网接入服务，提供这种服务的机构叫做 **ISP（Internet Service Provider，互联网服务提供商）**，比如中国移动、中国联通、中国电信，而宽带就是指运营商提供的固定互联网接入服务

>通常我们会说没有 WiFi 就得用流量，这里“流量”指的是移动蜂窝网络，附近的 4G/5G 基站能通过无线电信号与手机通信，基站再接入运营商的移动网络，让手机能够访问互联网

现在很多家庭使用光纤宽带，运营商可以把光纤一路铺设到你家，这叫 **FTTH（Fiber To The Home，光纤到户）**，但家里的路由器通常不能直接连到光纤上，中间还需要一台设备，负责连接运营商的光纤网络，并向家庭网络提供合适的接口，这就是我们常说的**光猫**，也叫**光网络终端（ONT）**，当然也有光猫和路由器二合一的设备

但是光纤不是唯一选择，以前还有 **DSL（数字用户线，Digital Subscriber Line）**，用电话线传数据，此外还有 Cable/HFC（利用同轴电缆和光纤）、卫星等接入技术

综上，互联网大致由以下三个部分组成
- **网络边缘**：电脑、手机等真正产生或使用数据的设备，这些能够运行网络应用的设备称为**主机（Host）**，也称**端系统（End System）**，包含客户端和服务器，服务器也是主机，只不过它主要负责向其他设备提供服务
- **接入网**：让主机接入更大的网络
- **网络核心**：由大量相互连接的网络设备和通信链路组成，负责把数据继续送往远处

# 网络寻址与路由转发

## MAC、IP 地址

假设现在要用手机给电脑无线传文件，你的手机只连接了附近的网络，它怎么知道远方的某台电脑在哪里？

实际上，每个网卡设备都有唯一的设备ID，称为 **MAC 地址**（全球唯一，不可修改），共 48 位，比如 `02:11:22:33:44:55` ，一台交换机可以获取到不同 MAC 地址对应自己的哪个接口，以后收到数据时，就能据此决定从哪个接口发送出去

但是，MAC 地址本身通常不能帮助我们直接判断一台设备属于哪个网络，就好比送快递，你知道要送给谁了，但是不知道他在哪，这时就需要 **IP 地址**，用来确定数据应该发送到哪个网络、哪个设备

需要注意，IP 地址只是一个逻辑上的地址，在全球范围内不一定唯一，但在同一个局域网内，IP 地址通常必须互不相同，以便进行区分

IP 地址也有着特定的格式，以 IPv4 为例，它由一串 32bit 的数字构成，通常分成四组，每组 8bit，十进制下写成：`192.168.1.10`

那为什么说这个地址能表示设备属于哪个网络呢？关键是其中的**网络前缀**，假设一个局域网采用 `192.168.1.0/24` ，这里 `/24` 表示：这个地址范围的前 24bit 用来表示网络前缀，即其中的 `192.168.1` ，这样一来，网络设备就可以先判断目标属于哪个网络，而不是从世界上所有设备里挨个查找

IPv4 总共只有 32bit ，能表示的地址数量有限，IPv6 则有 128bit ，提供大得多的地址空间

## 路由与转发

现在我们知道快递要往哪送、送给谁了，但是还不知道沿着什么路线走过去，这时候就需要进行**路由（Routing）**：网络中有收发信息的主机设备，和一堆中间节点，比如路由器、多个路由器构成的子网、ISP等，路由就是要找到一条通往目标主机的传输路径，通常将结果存储在**路由表**中

有了路径后，就看可以开始执行**转发（Forwarding）**：某个节点收到一个数据包后，查找路由表，将数据传给下一个节点

比如说有下面这样的几个设备

| 设备  | IP 地址                               |
| --- | ----------------------------------- |
| A   | `192.168.1.10`                      |
| B   | `192.168.1.60`                      |
| C   | `192.168.2.60`                      |
| 路由器 | 接口1：`192.168.1.1`，接口2：`192.168.2.1` |

![[计网/imgs/img1/image.png]]

- A → B：A 知道自己的 IP，又通过某种方式获知了 B 的 IP，对比网络前缀发现都是 `192.168.1` ，不需要经过路由器，局域网内就可以完成传输
- A → C：C 的网络前缀是 `192.168.2` ，和 A 的不同，于是 A 会先把数据发给局域网连接的路由器，路由器根据目标 IP 进行转发

# 数据交换方式

## 分组交换

数据传输时，通常会把大文件切成一堆小块，分别进行传输，这种在网络中独立传递的数据单位叫做**分组（Packet）**，也称数据包，一个分组通常不只包含真正的数据，还包含必要的控制信息，比如目标地址

有了这种划分，网络就能够让不同用户的数据包交替通过同一条链路，而不用等一个人完整传输完所有数据后才轮到别人，这便是互联网最重要的设计之一：**分组交换（Packet Switching）**

分组交换可以让大家能够共享有限的网络资源：假设一条链路每秒最多发送 100 个数据包，现在两个人正在使用它，用户 A 暂时不发送，用户 B 就可以使用更多的链路能力；等 A 也开始发送，两人的分组便可以交替通过，这种根据用户实际发送情况共享资源的方法，叫做**统计多路复用（Statistical Multiplexing）**

但即便共享了，资源也是有限的，比如每秒有 150 个包到达，而链路只能发走 100 个，剩下的包会暂时存放在路由器的缓冲区内，排成一个队列，但缓冲区的大小也是有限的，如果装不下了就只能扔掉新来的数据包，造成**丢包（Packet Loss）**

## 电路交换

分组交换很灵活，但有没有另一种方法，可以避免用户之间不断竞争资源？想象传统电话系统，我们可以先为通信双方建立一条连接，给它们预留通信资源，等通话结束再释放，这种方案叫做**电路交换（Circuit Switching）**，资源一旦分配给某个连接，即使暂时没有数据，也不会立刻分给其他用户

>电路交换还有 FDM（频分复用）与 TDM（时分复用）的机制，前者把不同频率范围分配给不同通信，后者把不同时段分配给不同通信

| | 电路交换 | 分组交换 |
|---|---|---|
| 资源 | 建立连接并预留资源 | 按实际发送情况共享 |
| 优势 | 已建立连接的资源较有保障 | 灵活、利用率高 |
| 缺点 | 空闲预留可能浪费资源 | 可能排队、丢包、时延波动 |
| 适合的流量 | 持续、需要稳定资源保障 | 大量间歇性、突发性流量 |

## 分组的存储与转发

分组交换的**存储-转发**机制：一台路由器需要先收到一个完整的分组，将这个分组暂时存储在缓冲区，检查分组的相关信息，再开始向下一个节点发送

这就存在一个延时：假设分组大小是 $L$ bit，链路每秒能够发送 $R$ bit，那么仅仅把完整分组发送到网络链路上，对于每个中间节点就至少需要耗时

$$
d_{\text{trans}} = \frac{L}{R}
$$

这个时间是**传输时延**，是指把分组送入链路需要多久，但不代表它已经到达另一端，信号沿着链路传播还需要额外时间

# 网络性能与服务质量

## 比特率、带宽、吞吐量

**比特率（Bit Rate）**：某个发送端每秒向信道发送多少比特，单位是 bps 
**带宽（Bandwidth）**：一条通信链路能够支持的最高数据传输速率
**吞吐量（Throughput）**：实际运行中时，每秒有多少数据通过
**有效吞吐量（Goodput）**：衡量真正有用的数据的传输速率，因为数据传输时还可能产生各种额外开销、重复传输，用户实际成功接收的有用文件数据可能更少

## 网络时延

**传输时延（Transmission Delay）**：发送设备把完整数据包送入链路所需的时间
**传播时延（Propagation Delay）**：数据进入链路之后，信号从线路一端传播到另一端所需的时间，比如电流沿着电线传播
**处理时延（Processing Delay）**：数据包到达路由器后，路由器还需要检查必要的信息、查找转发表等，然后才能继续转发，这些操作也需要时间
**排队时延（Queueing Delay）**：如果输出链路正忙，分组就需要排队等待

## 排队、丢包与 Little 定律

数据包会在路由器的缓冲区里排队，一个经典的排队关系是 **Little 定律**

$$
L=A\times W
$$

- $A$ ：数据包的平均到达速率
- $W$ ：每个包的平均等待时间
- $L$ ：平均等待的数据包的数量

## RTT、时延带宽积与抖动

**往返时延（RTT，Round-Trip Time）**：从发出请求开始，到收到回复为止经历的时间，可以用 `ping` 命令测试
**时延带宽积（Bandwidth-Delay Product）**：发送端持续发送数据，当数据的第一个 bit 首次到达时，链路中还在传输的数据量
**时延抖动（Jitter）**：先后发送的数据包，延迟可能不一样，比如视频通话时，声音的延迟分别是 20 ms、25 ms、22 ms，播放可能比较平稳，但如果突然变成 20 ms、180 ms、40 ms、250 ms，节奏就乱了，听起来会很奇怪

# 网络协议与分层架构

## 协议

电脑 A 向 B 发送一串数字，B 虽然收到了，却不知道它究竟表示一句文字、一张图片，还是一条操作指令，因此能够传递数字还不够，双方还必须约定好信息的格式与各部分的含义，这种共同遵守的通信规则，叫做**协议（Protocol）**，通常包含三要素
- 语法（Syntax）：消息的格式，比如有哪些字段
- 语义（Semantics）：消息和字段具体代表什么
- 时序（Timing）：双方什么时候发送、响应，操作遵循什么顺序

## 面向连接与无连接服务

**面向连接的服务**：通信之前先建立逻辑连接，准备好双方本次通信需要的状态，再开始交换数据
**无连接的服务**：不必事先建立连接，可以随时直接发送数据

>面向连接 ≠ 电路交换:电路交换讨论的是网络资源是否为通信双方预留；面向连接讨论的是通信双方是否需要先建立逻辑通信状态

## 分层架构

![[计网/imgs/img1/image-1.png]]

- 应用层：决定寄什么东西、向对方提出什么要求
- 传输层：负责整个寄送过程的交付规则，比如确认有没有丢件、顺序是否正确
- 网络层：负责规划包裹经过哪些中转站
- 接入层：负责每段路上由什么车、通过什么方式，把包裹运到下一站

不同层次对于传输的信息的称呼也不同
- 应用层：消息（message）
- 传输层：报文段（segment）
- 网络层：数据包、分组（packet）
- 接入层：帧（frame）
